Importing XML Logs

An XML export repeats one element per event — you name that record element, then locate each field by an element or attribute path such as @id or payload/user@id. The console shows live what every path extracts.

An XML source type treats each repeating element as one record. Every field is located by an element / attribute path; the five roles are the same as every other format. This guide covers the record element, path mapping and the whole-document delta. See guide 30 for the console overview.
1

The repeating record element

Open Source types → ＋ and 📄 Choose a file…. The console auto-detects XML and the record element — the element that repeats once per event (here <event>) — shown at the top of the mapping step.

XML record element: event
<log> <event id="20253471"> <ts>2015-01-09T19:12:06Z</ts> <payload><action>login</action></payload> </event> <event id="…"> … </event> </log>
2

Map fields by element / attribute path

The record's fields are listed as clickable paths. Pick a role tab and click a path — or type one. An attribute is addressed with a leading @; nested elements use /.

RolePathExtracted
EVENT_ID@id20253471
EVENT_TIMEts2015-01-09T19:12:06Z
STEPpayload/actionlogin
Meta 1payload/user@idu-77

Each path resolves to a single value, shown live — so a wrong path is obvious immediately.

Same five roles. EVENT_TIME is normalised to YYYY-MM-DD HH:MM:SS; EVENT_ID is stored MD5-hashed; up to three Metas carry business names; a Helper feeds compound rules only.
3

Compound steps work with paths too

Split one activity into several by another field — the conditions match on path values. Map the deciding field (e.g. a status attribute) as a Helper, then write rules in the STEP tab.

Rule 1 → login successful when payload/action is “login” · @status is “200”
Rule 2 → login failed when payload/action is “login” · @status is “500”

First matching rule wins; unmatched records keep the plain STEP value.

4

Import & re-import

Add a File source, link this source type, and press ▷. An XML file is a whole document, so it is import-once by content signature: re-running an unchanged file imports nothing; a changed file re-imports the whole document.

Importing…

The panel shows the records imported and when it last ran. Because events are never de-duplicated, re-importing a changed file adds its events again — to truly reload a project, delete it first (Connections → Projects) and import anew.

Good to know

  • Attributes vs elements. A leading @ selects an attribute (@id, payload/user@id); a bare path selects element text.
  • Live JOURNEYS preview. An example output row (id shown “stored as MD5”) confirms the whole spec before you save.
  • Compound rules are additive and case-insensitive except for “matches regex” — same as every format.
  • Sandboxed reads and import logging apply here too — see the overview (guide 30).

XML mapping mirrors JSON — click a path onto a role and read the live value — with attributes addressed by a leading @.
