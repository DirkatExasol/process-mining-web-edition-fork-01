Suite · MCP Server

Installing the MCP Server

The seventh surface: a Model Context Protocol endpoint that lets AI clients query your process-mining metrics, paths, cases and metadata, and read and write notes — authenticated with OAuth via Authentik. This guide takes you from an Authentik provider to a connected Claude Desktop.

The MCP server is off by default and adds no new credentials: it trusts an external OAuth provider, verifies each token against that provider's public signing keys, and maps it to an existing Process Mining user — so a caller sees exactly the connections that user is assigned, and never anything to write. This guide uses Authentik (Keycloak to follow) and Claude Desktop as the example client (other clients to follow).
1

What the MCP server is

The MCP server is a Model Context Protocol endpoint that lets AI clients (Claude, ChatGPT, …) query your Process Mining data — metrics, paths, cases, metadata and notes — over HTTP(S). It is the seventh surface, on the admin port +40, and it is off until an administrator enables it (it returns 503 while off). Callers authenticate with an OAuth access token from your Authentik server; the token is verified against Authentik's signing keys and mapped to a Process Mining user, whose assigned database connections decide what they may see. Its only writes are notes (create_note, update_note) — there are no ingest, event-edit or sampling tools — and five deeper-analysis tools are reserved for power users.

Same boundary as the app. A caller never sees more than the mapped user's assigned connections — exactly what that person could open in the main app — and can change nothing but notes, under the app's own note rules.
2

What it exposes (the tools)

Nineteen tools in five groups. Everyone may use the discovery, analysis, case and note-reading tools. Notes are the only writes: create_note and update_note follow the app's note rules (you are the author, threads are append-only, only the author changes severity or scope), validate every field, and are rate-limited and logged. The five power-analysis tools answer only users with the power-user role (and admins); others get a polite refusal. Most tools take connectionId + projectId and the common filter. Note times are local (Admin Console display timezone) with the UTC offset.

3

Prerequisites

Before you touch the MCP tab, make sure the pieces it relies on are in place:

  • An Authentik server reachable from the Process Mining host (this guide assumes https://authentik.example.com:19443).
  • Administrator access to both Authentik and the Process Mining admin console.
  • Each MCP user must already exist and be enabled in Process Mining (Users tab) with the same username the token will carry.
  • That user must be assigned the connection(s) they should query (Database Connections tab).
  • TLS enabled in the admin (TLS / SSL tab) so the HTTPS endpoint (:18493) is live — OAuth clients require HTTPS.
No PM user, no access. The token only authenticates who the caller is; the matching Process Mining user (and its connection assignments) is what grants any data at all. A valid token for a username with no PM account gets 403.
4

Part A — Configure Authentik

Create a dedicated OAuth2/OpenID provider and an application in front of it, then note the endpoints the MCP server will trust.

1 · Create an OAuth2/OpenID Provider  —  Applications → Providers → Create → OAuth2/OpenID Provider

FieldValue
NameProcess Mining MCP
Authorization flowyour standard explicit- (or implicit-) consent flow
Client typePublic (PKCE, recommended for interactive clients) — or Confidential if the client stores a secret
Signing keyan RSA key → the access token is a signed RS256 JWT the server verifies offline
Scopesopenid, profile, email (+ offline_access for refresh tokens)
Redirect URIsthe callback(s) your client uses — for Claude, see Part C

2 · Create an Application bound to that provider  —  Applications → Applications → Create. Name Process Mining MCP, slug e.g. process-mining-mcp. Under Bindings, restrict who may use it (e.g. bind a group process-mining-users).

3 · Note the endpoints (all under …/application/o/process-mining-mcp/):

Issuer     https://authentik.example.com:19443/application/o/process-mining-mcp/
Discovery  <issuer>/.well-known/openid-configuration
JWKS       <issuer>/jwks/
Set an Audience (recommended). Authentik only sets the token's aud if you add an audience via a scope/property mapping. Do it and put the client id in the MCP Audience field: it ties each token to this application, so a token minted for another app on the same Authentik can't be replayed here. Leave it blank and the aud check is skipped (still gated by issuer, signature, user-mapping and group).
5

Part B — Configure the MCP server (admin console)

Open the admin console → MCP Server tab and fill in the Authentik (OAuth) settings. No secrets are stored here — only these public coordinates, because tokens are validated offline against the JWKS.

FieldWhat to enter
Issuer URLhttps://authentik.example.com:19443/application/o/process-mining-mcp/
JWKS URLblank to auto-discover from the issuer, or paste …/jwks/
Audience / Client IDthe client id (recommended, once you mapped aud); blank skips the check
Required groupoptional — only members of this Authentik group may connect (matched against the token's groups)
Username claimthe JWT claim matched to a PM username — default preferred_username; use email if usernames are email addresses

Then: Save settings → Test Authentik (fetches the discovery document and JWKS and reports the signing-key count — fix any error first) → tick Enable the MCP server. Enabling/disabling is immediate; no restart.

A TLS change needs a restart. Turn TLS on in the TLS / SSL tab; the change takes effect after ↻ Restart app server (App Control). Enabling or disabling the MCP server itself does not.
6

Behind a reverse proxy (optional)

The MCP server listens on its own port. To publish it under a public domain path — e.g. https://pm.example.com/mcp — a proxy must preserve the /mcp path and send forwarding headers so the OAuth discovery document advertises the public URL, not the internal host:port.

location /mcp {
    proxy_pass https://127.0.0.1:18493;   # NO trailing slash — keep the /mcp path
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host  $host;
}
location = /.well-known/oauth-protected-resource     { proxy_pass https://127.0.0.1:18493; proxy_set_header X-Forwarded-Host $host; proxy_set_header X-Forwarded-Proto $scheme; }
location = /.well-known/oauth-protected-resource/mcp { proxy_pass https://127.0.0.1:18493; proxy_set_header X-Forwarded-Host $host; proxy_set_header X-Forwarded-Proto $scheme; }

A trailing slash on proxy_pass strips the prefix and the backend answers 404 {"detail":"Not Found"}. The server also answers at the root as a fallback, so a stripping proxy still works — but preserving the path is cleaner. Route /mcp, the two well-known paths and /health.

  • Point the client at the public URL (https://pm.example.com/mcp).
  • Or skip the proxy and expose the port directly (https://<host>:18493/mcp) if your firewall allows it and TLS is on.

Part C — Add the server to Claude Desktop

Claude is the example client here; any MCP client that supports remote (HTTP) servers with OAuth follows the same shape (more client walkthroughs to follow).

#In Claude Desktop
1Settings → Connectors → Add custom connector.
2Name Process Mining · URL https://<your-host>:18493/mcp (or your proxy URL).
3Save and click Connect. Claude reads the server's /.well-known/oauth-protected-resource, opens Authentik's sign-in, and stores the token after you approve.
4Enable the connector in a chat and ask e.g. “list my process-mining connections”, then “show the process map for project 1 on connection c1”.

Add Claude's OAuth redirect URIs to the Authentik provider (Part A): https://claude.ai/api/mcp/auth_callback, https://claude.com/api/mcp/auth_callback, and for the desktop app a local loopback such as http://localhost:* — use the exact value Claude shows you if it differs.

The token is the user. Whoever signs in at Authentik must match an enabled Process Mining user (by the configured username claim). Claude then sees exactly that user's connections — nothing more.

Verifying by hand

Two quick checks from a shell confirm the endpoint is live and discoverable before you involve a client (-k accepts the self-signed internal certificate):

# liveness (unauthenticated) → {"ok":true,"enabled":true}
curl -k https://<your-host>:18493/health

# OAuth discovery (unauthenticated) → the Authentik authorization server
curl -k https://<your-host>:18493/.well-known/oauth-protected-resource

# a real call, with a token you already obtained from Authentik
curl -k -X POST https://<your-host>:18493/mcp \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"list_connections","arguments":{}}}'

Troubleshooting

The common failures and where to fix them:

SymptomCause / fix
503 The MCP server is disabledEnable it in the admin MCP Server tab.
401 + a WWW-Authenticate headerNo/invalid token — the client should run the OAuth flow. Check issuer/JWKS and press Test Authentik.
403 No enabled Process Mining user matches '…'The token's username claim doesn't match an enabled PM user. Create it (Users tab) with that exact name, or change the Username claim (e.g. to email).
403 …not in the group requiredThe user isn't in the configured Required group in Authentik.
Connection … is not assigned to youAssign the connection to the user (Database Connections tab).
Test can't reach AuthentikWrong issuer URL, or the host can't reach :19443. The URL and network path must be right.

Good to know

  • Keycloak (and other OIDC providers) to follow. This guide uses Authentik, but the MCP server trusts any provider that issues RS256 JWTs with a JWKS endpoint — so Keycloak already works today with the equivalent settings; a dedicated Keycloak walkthrough is coming.
  • More clients to follow. Claude Desktop is the worked example; the same custom-connector pattern applies to any client that supports remote HTTP MCP servers with OAuth.
  • Tuning env vars: PMW_MCP_MAX_ROWS (default 1000) caps rows returned per call; PMW_MCP_JWKS_CACHE_SECS (default 3600) sets how long signing keys are cached.
  • Token integrity does not depend on TLS. Tokens are verified cryptographically against Authentik's JWKS (RS256); only the JWKS transport skips certificate verification (Authentik is a trusted internal host).

Rule of thumb: get curl -k https://<host>:18493/health returning {"ok":true,"enabled":true} first — then add the connector in Claude.
