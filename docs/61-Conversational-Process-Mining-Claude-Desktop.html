Conversational Process Mining

Claude Desktop: connect & ask

Add the Process Mining MCP server as a Connector in Claude Desktop, sign in with OAuth, and start asking about your processes in plain language — with example queries to get you going.

This is everything you need to start working with Conversational Process Mining from Claude Desktop: add the connector, sign in through your OAuth provider, and ask. It assumes an administrator has already enabled the MCP server (guide 15); for the concept and what you can ask, see guide 60.
1

Before you start

This guide is the user side of Conversational Process Mining — connecting Claude Desktop to the Process Mining MCP server. A few things must already be true (an administrator handles the first three; see guide 15):

  • The MCP server is enabled and reachable over HTTPS (e.g. https://<host>:18493/mcp or a proxied https://pm.example.com/mcp).
  • It is wired to your organisation's OAuth provider (Authentik) — the same sign-in you already use.
  • You have a Process Mining account that is enabled and assigned at least one database connection.
  • You have Claude Desktop installed and are signed in to Claude.
Know your server URL. Ask your administrator for the exact MCP URL (the direct :18493/mcp or the public proxy path). You'll paste it in the next step.
2

Add the Process Mining connector

Claude Desktop calls MCP servers Connectors. Add the Process Mining server as a custom connector once; it stays available afterwards.

#In Claude Desktop
1Open Settings → Connectors.
2Click Add custom connector.
3Name: Process Mining.
4URL: the MCP endpoint your admin gave you, e.g. https://<host>:18493/mcp.
5Click Add / Save, then Connect.

Claude reads the server's /.well-known/oauth-protected-resource document, discovers your OAuth provider, and opens its sign-in page.

3

Sign in with OAuth

Connecting triggers the standard OAuth flow — the same as signing in to any web app. Your database password is never involved.

Connect ─▶ Authentik sign-in opens ─▶ you approve ─▶ Claude stores the token
                                                     └─ the Process Mining tools appear

After you approve, the connector shows as connected and its tools (list_connections, get_process_map, find_journeys, …) become available in chats.

Signed in as you. Whoever authenticates must match an enabled Process Mining user. Claude then sees exactly that user's assigned connections — nothing more. If sign-in fails or says no user matches, see Troubleshooting.
4

Enable it in a chat

Connectors are enabled per conversation. Start a new chat, switch the Process Mining connector on (the connector/tools control in the message box), and you're ready to ask. The first time the agent calls a tool, Claude may ask you to allow it — approve it to continue.

Reads freely, writes only notes. Every Process Mining tool only reads, except create_note and update_note, which add or change notes as you (rate-limited and logged). If your client lets you set permissions per tool, keep approval on for those two and let the read tools run without asking.
5

Start asking — example queries

You never name the tools; ask in plain language and the agent picks them. Good openers, roughly in the order you'd explore a new process:

Orient yourself

"List my process-mining connections and the projects on each."
"Which project has the most journeys?"
"What do the meta attributes mean in project 1, and what date range does the data cover?"

Understand the process

"Show me the process map for project 1 on connection Prod."
"What are the ten most common paths, and how often does each happen?"
"Which transitions are the slowest by median time?"

KPIs & health

"How many journeys in the last 30 days, and what's the process-goodness score?"
"Give me the average and median end-to-end duration."

Drill down to real cases

"List the five slowest cases that visited 'Payment Failed', with their paths."
"Show me the full trace of the first one."

Notes & review

"What open notes are on this process, grouped by severity?"
"Show me the shared URGENT and IMPORTANT notes, but not my personal ones."
Name the connection and project. When you have more than one (“on connection Prod, project 1”) so the agent doesn't have to guess.
6

Keep the conversation going

The value is in the follow-ups — each answer sets up the next question, and the agent chains the tools for you across the whole chat.

  • Narrow it — “only March”, “just the cases where department = Finance”, “exclude journeys that hit Cancelled”.
  • Compare — “how does the sample set compare with the full data?”
  • Explain — “why is that transition slow — show me a few example cases”.
  • Summarise — “write a short bottleneck summary I can paste into a ticket”.
7

Troubleshooting

If a connection or a query doesn't behave, it's almost always one of these:

SymptomLikely cause / fix
Connector won't connect / keeps asking to sign inThe MCP server may be disabled or unreachable, or the OAuth settings are off. Ask your admin to check the MCP Server tab (guide 15) and press Test Authentik.
“No enabled Process Mining user matches …”Your token's username doesn't match a Process Mining account. Ask your admin to create the user with that exact name (or align the Username claim, e.g. to email).
“…not in the group required”Your account isn't in the Authentik group required for MCP access — ask your admin to add you.
“Connection … is not assigned to you”That database connection isn't assigned to your user — ask your admin to assign it.
The agent won't call a toolMake sure the Process Mining connector is switched on in this chat, and approve the tool call when Claude asks.
Two-minute smoke test. An admin can confirm the server from a shell: curl -k https://<host>:18493/health should return {"ok":true,"enabled":true}.
