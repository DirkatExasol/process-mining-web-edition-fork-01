Importing JSON Logs

A JSON export is already structured — so each field is located by a JSON path such as user.id or items[0].sku. The console lists the record's paths for you to click, and shows live what each one extracts.

A JSON source type reads either a top-level array [ … ] or JSONL / NDJSON (one object per line). Each field is located by a JSON path; the five roles are the same as every other format. This guide covers the shape, path mapping and the whole-document delta. See guide 30 for the console overview.
1

Two JSON shapes

Open Source types → ＋ and 📄 Choose a file…. The console auto-detects JSON and which shape it is: a top-level array, or JSONL / NDJSON with one object per line. Pick one record as the example.

JSON array
[ { "ts": "2015-01-09T19:12:06Z", "user": {"id": 20253471}, "action": "login" }, { … } ]
JSONL / NDJSON
{"ts":"…","user":{"id":…},"action":"login"} {"ts":"…","user":{"id":…},"action":"basket"}
2

Map fields by JSON path

On the mapping step the record's fields are listed as clickable paths. Pick a role tab, then click a path to map it — or type one in the field row. Nested keys use dots and array items use [n].

RoleJSON pathExtracted
EVENT_TIMEts2015-01-09T19:12:06Z
EVENT_IDuser.id20253471
STEPactionlogin
Meta 1items[0].skuBK-4213

Each path resolves to a single value; the row shows it live, so a wrong path is obvious immediately.

Same five roles. EVENT_TIME is normalised to YYYY-MM-DD HH:MM:SS; EVENT_ID is stored MD5-hashed; up to three Metas carry business names; a Helper feeds compound rules only.
3

Compound steps work with paths too

Just like Text, you can split one activity into several — but the conditions match on path values instead of regex captures. Map the deciding field (add it as a Helper on the spot), then write rules in the STEP tab.

Rule 1 → login successful when action is “login” · status is “200”
Rule 2 → login failed when action is “login” · status is “500”

First matching rule wins; unmatched records keep the plain STEP value.

4

Import & re-import

Add a File source, link this source type, and press ▷. How re-runs behave depends on the shape:

  • JSONL / NDJSON — read line by line, so re-running imports only the appended lines (byte-offset delta), exactly like Text.
  • JSON array — a whole document, so it is import-once by content signature: re-running an unchanged file imports nothing; a changed file re-imports the whole document.
Genuine reload. Events are never de-duplicated, so to truly reload a project delete it first (Connections → Projects) and import again.

Good to know

  • Click, don't type. The console lists every path in the sample record — mapping is usually just clicking a path onto the active role.
  • Live JOURNEYS preview. An example output row (id shown “stored as MD5”) confirms the whole spec before you save.
  • Compound rules are additive and case-insensitive except for “matches regex” — same as every format.
  • Sandboxed reads and import logging apply here too — see the overview (guide 30).

JSON mapping is click-driven: the record's paths are listed, you click one onto a role, and the live value confirms it — no regex required.
