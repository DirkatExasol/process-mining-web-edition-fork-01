Conformance Check

Lay target values over the process map and see, edge by edge, whether reality meets them — green where it does, red where it doesn't — then open the gap-analysis table to fix the worst first.

Conformance Check overlays your norms (targets) on any transition metric and colours each edge by whether the actual value meets its target. You set the norms in Edit mode, choose whether each is a ceiling or a floor, and read the gap analysis — violations first. For the exact maths behind “actual” and “delta”, see guide 81 — Conformance Explained.
1

What it does

Conformance Check lays your target values (“norms”) over the process map and shows, edge by edge, whether the real process meets them — green where it does, red where it breaks the target. Switch the metric with the chips at the top; norms are stored per project and per metric.

# Count% Journey % ⏱ Avg Time⌄ Min⌃ Max
Payment Processing→ 82% ≤ 90% ✓ Confirmed
Payment Processing→ 18% > 10% ✗ Failed
Open it from the ☰ menu → Conformance Check (an advanced view for Power users and admins).
2

Set the norms

Toggle Edit norms, click an edge, and type its target. For the Count metric a norm is a percentage of the traffic leaving that source step, and the editor shows a live remaining % — how much is already assigned to the step’s other out-edges and how much is left before it exceeds 100 %. Time metrics take an absolute value in seconds.

Browse Catalog→Add to Basket 35 % remaining for this step: 5 %

Two other edges from Browse Catalog already take 95 % — type more than 5 % and the editor warns you in red that the step’s norms would exceed 100 %.

3

Ceiling or floor

By default a norm is a maximum — the actual value must stay at or below it (red when it exceeds). Flip Norm is a minimum and the whole view reverses: the actual must be at least the norm (red when it falls short). Same numbers, opposite meaning — pick the reading that matches how your targets are phrased.

Norm is a minimum ◯ Shipped → Delivered: 93 % · norm 95 %

As a maximum: 93 ≤ 95 → ✓ · as a minimum: 93 < 95 → ✗ (2 % of shipments never arrive).

5

Where it goes

Conformance is more than a one-off view — it feeds the rest of the suite and travels with your setup:

  • The gap analysis is appended to the AI supported Documentation report (one table per metric that has norms), following the same ceiling/floor reading you chose.
  • Norms round-trip through Backup & Restore, so a target model built once can be shared or moved between installations.
  • Only edges that have a norm are judged — the rest are neutral (never counted as compliant or as a violation).
How are actual, delta and colour computed? The exact per-metric rules (branching share for Count, absolute seconds for time, the 100 % budget) are in guide 81 — Conformance Explained.

Good to know

  • Count norms are a 100 % budget. Because they’re shares of one step’s outgoing traffic, the norms leaving a step should sum to at most 100 % — the editor enforces this as you type.
  • Per project, per metric. Each metric carries its own independent target set; switching the metric chip switches the whole conformance picture.
  • Advanced view. Conformance Check is available to Power users and administrators (see the Users & Permissions guide).
  • It measures, it doesn’t change. Norms are targets laid over the real data — defining them never alters your process.

Conformance turns a target operating model into something the map checks continuously — every reload re-judges the live process against the same yardstick.
